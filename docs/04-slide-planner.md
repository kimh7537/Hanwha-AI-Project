# 04. 모듈 C — Presentation Planner AI (`slide-planner`)

**담당 파일:** `backend/app/services/planner.py`, `backend/app/prompts/planner.py`,
`backend/app/services/export_pptx.py`(선택), `backend/fixtures/slide_deck.json`, `backend/tests/test_planner.py`
**입력:** `AudienceContent` + `SourceAnalysis` + `PresentationRequest` · **출력:** `SlideDeck` → `docs/01-contracts.md`

## 권장 기본 구성

1. 발표 목적 / 문제 배경
2. 기술 또는 해결 방식
3. 작동 원리 / 핵심 내용
4. 주요 장점 또는 가치
5. 결론 및 다음 행동

## 분량 원칙 — 시간이 상한, 청중이 밀도

| 발표 시간 | 기본 장수 | 구성 원칙 |
|---|---|---|
| 3분 | 4장 | 결론 우선 |
| 5분 | 5장 | 핵심 원리와 효과 포함 |
| 10분 | 7장 | 배경·사례·리스크 추가 |

여기에 **청중 보정**을 더한다. 시간은 상한을 정할 뿐 배분까지 정하지 않는다.

| 청중 | 보정 | 이유 |
|---|---|---|
| 신입사원 | +1 | 사전 지식을 가정할 수 없어 한 단계를 더 쪼갠다 |
| 실무자 | +1 | 적용 조건·예외를 빠뜨리는 것이 분량이 느는 것보다 위험하다 |
| 임원 | −1 | 결론으로 압축한다 |
| 고객 | 0 | — |

결과적으로 5분 발표라도 신입 6장 / 임원 4장이 된다. **청중을 바꾸면 장수·순서·정보 선택이
같이 바뀌어야 한다** — 표현만 바뀌면 "프롬프트 옵션을 UI로 만든 것"과 구분되지 않는다.

`request.slide_count`가 주어지면 그 값을 우선하고 **청중 보정을 걸지 않는다**(사용자 지정이
우선). 최종값은 3~10장으로 클램프한다.

## 구성 전략 (`SlideDeck.strategy`)

덱이 **왜 이 순서·이 분량인지**를 2~3문장으로 남긴다. 화면의 "AI 구성 전략" 카드에 그대로
노출되며, 청중을 바꾸면 이 문장이 함께 바뀌는 것이 차별화의 증거다.

- 원문 사실을 적는 칸이 **아니다.** 설계 의도만 적으므로 `source_refs`가 없고 검증 대상도 아니다.
- LLM 이 비워 두거나 한 줄로 때우면 `build_strategy()` 의 규칙 문장으로 덮는다.
  이 칸이 비면 화면에서 근거가 사라지므로 빈 채로 두지 않는다.

## 슬라이드 규칙

- `takeaway`는 **한 문장**이며 그 슬라이드에서 청중이 가져갈 결론이다.
- `bullets`는 3~5개, 각 40자 내외. 문단을 그대로 붙여넣지 않는다.
- **모든 슬라이드는 `source_refs`를 1개 이상 갖는다.** (데모 성공 기준 4번)
- `visual_suggestion`은 "무엇을 그릴지"를 한 줄로. 이미지 생성은 하지 않는다.
- `speaker_notes`는 모듈 D가 스크립트로 확장할 씨앗 문장 수준으로 짧게 둔다.
- 필수 키워드(`request.keywords`)는 최소 1회 이상 덱 안에 등장해야 한다.

## 렌더링

React 기반 HTML preview가 1순위. `python-pptx` PPTX export는 **다른 모든 것이 끝난 뒤에만** 손댄다.
export가 미구현이어도 JSON / Markdown 다운로드로 데모가 성립해야 한다.

### PPTX export (`app/services/export_pptx.py`, 구현됨)

`GET /api/presentations/{id}/export/pptx` — 저장된 `GenerateResponse` 를 그대로 배치한다.

- **export 는 새 문장을 만들지 않는다.** 요약·재작성을 하면 검증을 마친 문장과 파일 내용이
  달라져 `source_refs` 대응이 깨진다. 넘칠 때는 문장을 자르지 말고 글자 크기를 줄인다.
- 구성: 표지 → 본문 슬라이드 → 부록(예상 Q&A) → 부록(원문 대비 검증).
- 본문 슬라이드 하단에 `추천 시각자료` 와 `원문 근거: chunk-…` 를 항상 인쇄한다.
- 발표자 노트에는 모듈 D 의 스크립트·꼭 말할 것·근거가 들어간다.
- 고객 청중이면 표지에 `공개 전 검토 필요` 를 **글자로** 남긴다(색만으로 구분하지 않는다).
- 한글 글꼴은 `a:latin` 만으로는 적용되지 않는다. `a:ea`(동아시아) 도 함께 지정한다.
- 화면 라벨은 `frontend/lib/labels.ts` 가 원본이고 `app/services/labels.py` 가 미러다.
  둘이 어긋나면 `tests/test_labels_mirror.py` 가 잡는다.

### 입력이 PPTX 면 원본 위에 얹는다

빈 프레젠테이션에 새로 그리면 사용자가 만들어 둔 이미지·표·배경·글꼴이 전부 사라진다.
그래서 원본 PPTX 바이트를 `StoredDocument.source` 에 들고 있다가 export 에 넘긴다
(`build_pptx(result, template=...)`).

- 생성 슬라이드는 `source_refs → chunk.page` 로 원본 슬라이드에 1:1 로 붙는다.
  PPTX 파싱은 슬라이드 1장 = 페이지 1개이므로 페이지 번호가 곧 슬라이드 번호다.
- 원본 슬라이드에서 **텍스트 프레임의 글만** 바꾼다. 표(GraphicFrame)·그림에는 text_frame 이
  없어 후보에서 저절로 빠지고, 그래서 원본의 표·이미지는 손대지 않는다.
- 글꼴은 원본 첫 run 의 `rPr` 을, 글머리는 첫 문단의 `pPr` 을 복사해 물려준다.
  넘칠 것 같으면 원본 크기를 기준으로 줄인다 — 여기서도 문장은 자르지 않는다.
- 제목은 `shape_id` 로 거른다. `shapes.title` 은 호출마다 새 proxy 라 `is` 비교가 통하지 않고,
  그대로 두면 제목 자리에 본문 bullet 이 들어간다.
- 본문 텍스트 상자가 없는 슬라이드(표·그림 전용)는 도형이 없는 가장 넓은 세로 구간에 글을 얹는다.
  놓을 자리가 없으면 그 슬라이드만 생성 레이아웃으로 새로 그린다.
- 발표 시간에 맞춘 덱이므로 **짝이 없는 원본 슬라이드는 빠진다.** 원본 그대로가 필요하면
  원본 파일을 쓰면 된다.
- 슬라이드 크기는 원본을 따른다(4:3 원본을 16:9 로 늘리면 배치가 깨진다). 원본이 없거나
  열리지 않으면 지금까지처럼 16:9 빈 프레젠테이션에 새로 그린다.

## mock / fallback 동작

휴리스틱 경로는 `AudienceContent.explanations`와 `SourceAnalysis`의 항목을 위 5단 구성 슬롯에
분배해 덱을 만든다. 각 슬라이드의 `source_refs`는 사용한 항목의 refs를 합집합으로 승계한다.

## 완료 조건

5분·고객 조건으로 5장 안팎이 생성되고, 모든 슬라이드에 유효한 `source_refs`가 있으며,
`request.keywords`가 덱 안에 등장한다.
