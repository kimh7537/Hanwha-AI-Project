# 07. UI/UX 요구사항 (`frontend-integrator`)

**담당 파일:** `frontend/app/**`, `frontend/components/**`, `frontend/lib/{types,api,labels}.ts`

## 위저드 흐름 (한 화면)

```
[1. 문서 업로드]
      ↓
[2. 발표 조건]  청중 / 목적 / 시간 / 키워드 / 스타일 / 원어 유지 / 슬라이드 수
      ↓
[3. 생성 중]    문서 분석 → 청중 변환 → 슬라이드 설계 → 발표 지원 → 검증
      ↓
[4. 결과]       탭: 발표자료 | 청중 비교 | 발표 스크립트 | 예상 Q&A | 정확성 검증
```

## 결과 화면 요구사항

- 발표자료 탭 맨 위에 **`AI 구성 전략`(`slide_deck.strategy`)** 카드를 둔다. "왜 이 순서·이 분량인가"가
  보이지 않으면 청중 조건이 그냥 프롬프트 옵션처럼 읽힌다.
- **청중 비교 탭**: 같은 원문·같은 조건에서 **청중만 바꿔** 다시 생성해 좌우로 세운다. 각 열에
  청중 라벨 · 장수 · 구성 전략 · 슬라이드 제목과 takeaway 목록을 둔다. 장수와 순서가 다르다는 것이
  한 화면에서 보여야 한다. 전용 엔드포인트를 만들지 않고 `generate`를 한 번 더 호출한다.
- **원본과 비교** 버튼은 **다운로드 줄에 두지 않는다.** PPTX·Markdown·JSON 옆에 같은 모양으로
  서 있으면 파일 저장 버튼으로 읽혀 아무도 누르지 않는다. 파일을 만드는 기능이 아니라 **보는**
  기능이고 결과를 훑는 내내 손에 닿아야 하므로, 스크롤을 따라오는 탭 줄 오른쪽 끝에 강조색
  테두리로 따로 세우고(탭이 아니므로 `role="tablist"` 밖) 탭 줄 아래 한 줄로 무엇을 보여주는지
  적는다.
- **원본과 비교**(버튼 → 전체 화면 오버레이): 왼쪽에 업로드한 원본 한 장, 오른쪽에
  그 자리에 들어간 발표용 슬라이드를 나란히 둔다. 각 쌍은 `다시 씀` / `새로 구성` / `제외됨`
  중 하나이며, 상태는 색과 함께 **글자로도** 읽혀야 한다. 짝짓기 규칙은 백엔드
  `export_pptx._source_slide_index`(슬라이드의 `source_refs` 가 가장 많이 가리키는 원본 쪽)와
  같아야 한다 — 화면이 실제로 내려받는 PPTX 의 동작을 그대로 설명해야 하기 때문이다.
  X 버튼과 Esc 로 닫으며, 닫으면 뒤의 결과 화면이 보던 탭 그대로 남는다.
- **비교는 글이 아니라 슬라이드 이미지로 한다.** 양쪽 모두 실제 PPTX 를 렌더링한 PNG 를 띄운다
  (`GET /api/documents/{id}/slides/{page}`, `GET /api/presentations/{id}/slides/{number}`).
  제목·bullet 만 좌우로 세우면 표·도형·배경이 어떻게 바뀌었는지 안 보인다.
  다만 이미지에 기대지 않는 길을 항상 남긴다 — 이미지 요청이 실패하면(PowerPoint 없는 PC 는
  503) 그 칸만 조용히 글자 비교로 되돌아가고, 헤더의 `글자로 보기` 로 언제든 전환할 수 있다.
  글자 비교의 왼쪽 글은 chunk 가 아니라 `DocumentResponse.pages` 에서 온다(chunk 는 쪽 경계를 넘는다).
  입력이 PPTX 가 아니면 원본 이미지가 없으므로 글자 비교만 쓴다.
- **한 번에 한 쌍만, 크게 띄운다.** 여러 쌍을 세로로 쌓으면 슬라이드가 손톱만 해져 무엇이
  달라졌는지 눈으로 잡히지 않는다. 위쪽 **탭 줄**(장 번호 + 제목 + 상태)에서 장을 고르고,
  화면 가운데에는 고른 한 쌍만 둔다. `←` `→` 로도 넘기고 아래에 `이전 장 / n / N / 다음 장`
  을 둔다(탭 줄은 `role="tablist"`, 화살표는 입력란 안에서는 가로채지 않는다).
- **달라진 자리는 이미지 위에 빨간 네모로 그린다.**
  `GET /api/presentations/{id}/slides/{number}/diff?page=` 가 두 렌더를 픽셀로 대조해
  0~1 비율 좌표를 준다. 결과 슬라이드는 원본의 **글만** 갈아 끼운 것이라 좌표계가 같아서
  네모 한 벌을 좌우 양쪽에 그대로 얹는다 — 눈이 같은 자리를 오가며 비교한다.
  네모는 도형 단위로 갈라져 `제목` / `본문` / `본문 추가` / `원문 근거 추가` 이름을 갖는다.
  **색만으로 알리지 않는다**: 네모마다 번호를 붙이고 그 아래 `달라진 자리 N곳` 목록에
  같은 번호와 이름을 글자로 적는다. 헤더의 `변경 표시` 토글로 끌 수 있고, 대조가 실패하면
  네모 없이 이미지 비교가 그대로 동작한다.
- 각 슬라이드에 **제목 / takeaway / 본문 bullet / 추천 시각자료 / 원문 근거**를 표시한다.
- 원문 근거 배지에는 `chunk-03` 이 아니라 **원문 위치(`3쪽`)**를 적는다. `chunk` 는 내부 식별자라
  발표를 보는 사람에게 아무 뜻이 없고, 눌러 볼 것이라는 짐작조차 주지 않는다. 한 슬라이드가 같은
  쪽에서 문장을 둘 이상 끌어오면 그때만 `3쪽 (1)`처럼 번호를 붙이고, 쪽을 못 찾은 근거는 지우지
  않고 식별자 그대로 남긴다(추적을 끊는 것보다 낫다). 배지를 클릭하면 **원문 문장과 쪽 번호**를
  보여주고, 식별자는 그 안에 작게 남겨 로그·JSON 과 맞춰 볼 수 있게 한다.
  같은 규칙을 Markdown(`lib/export.ts`)과 PPTX(`export_pptx._refs_label`) 에도 쓴다 —
  내려받은 파일에 `chunk-02` 가 찍히면 화면에서 고친 뜻이 없다.
- 검증 탭은 **색만으로 상태를 구분하지 않는다.** `확인됨` / `주의` / `검토 필요` 텍스트 라벨 필수.
- 청중이 `고객`이면 **"공개 전 검토 필요" 배지**를 결과 상단에 표시한다.
- 로딩 단계(5단계)와 오류 원인을 사용자 친화적인 **한국어**로 표시한다.
- 신뢰도 점수는 산식이 구현된 경우에만 표시한다. 없으면 표시하지 않는다.

## 디자인 방향

**기본은 다크**, 라이트는 사용자가 헤더의 토글(`components/ThemeToggle.tsx`)로 고를 때만 켠다.
`prefers-color-scheme` 분기는 두지 않는다 — 시연 화면이 발표자 노트북의 OS 설정에 따라
제멋대로 바뀌면 안 된다. 선택은 `<html data-theme="light">` 와 `localStorage.theme` 이 들고,
`app/layout.tsx` 의 인라인 스크립트가 첫 그림 전에 입혀 다크 한 번 깜빡임을 막는다.
오렌지 포인트 색상(`--accent`)을 강조에만 쓰고 배경은 무채색 + 은은한 오로라 그라디언트로 깔린다.

라이트는 다크 값을 그대로 뒤집지 않는다. `#ff8a3d` 는 흰 바탕에서 대비가 2:1 대까지 떨어져
본문 색으로 못 쓰므로, 색조는 유지한 채 어둡게 내려 잡는다(`--accent: #b8530c`). 흰 알파에
기대던 효과(오로라·격자·glass·shimmer)만 `:root[data-theme="light"]` 에서 다시 잡고,
컴포넌트는 토큰 클래스만 쓰므로 손대지 않는다. 브라우저 기본 위젯은 테마별 `color-scheme` 이
맞춘다 — `viewport` 에 `colorScheme` 을 박아 두면 라이트에서 위젯만 다크로 남는다.

색·질감은 전부 `frontend/app/globals.css` 의 CSS 변수와 `@theme inline` 매핑에서 나온다.
컴포넌트는 `bg-surface` / `border-line` / `text-accent` 같은 토큰 클래스만 쓰므로,
토큰을 바꾸면 화면 전체가 한 번에 바뀐다. 효과는 새 의존성 없이 순수 CSS 로만 만든다
(glass, `fade-up` 등장, 광택 스윕, shimmer 스켈레톤).

접근성은 연출보다 우선이다. `prefers-reduced-motion` 이면 애니메이션을 모두 끄고,
`:focus-visible` 외곽선을 유지하며, 상태는 **색만이 아니라 텍스트 라벨을 병행**한다.

## 타입 동기화

`frontend/lib/types.ts`는 `backend/app/models/contracts.py`의 미러다. 한쪽만 고치지 않는다.
→ `/contract-sync` 스킬 및 PostToolUse 훅이 이를 감시한다.

wire 값은 영문(`customer`), 화면 라벨은 한국어(`고객`). 매핑은 `frontend/lib/labels.ts` 한 곳에만 둔다.

## API 연결

`NEXT_PUBLIC_API_BASE_URL`로 백엔드를 가리킨다. **API 키를 프론트엔드에 두지 않는다.**
생성은 `POST /api/presentations/generate`, 검증은 `POST /api/presentations/verify`로 이어서 호출하고
5단계 진행 표시를 그에 맞춰 갱신한다.

## 오류 처리 문구 예시

| 상황 | 표시 문구 |
|---|---|
| 미지원 확장자 | "PDF, PPTX, TXT 파일만 업로드할 수 있습니다." |
| 구버전 `.ppt` | "구버전 PowerPoint(.ppt) 파일은 지원하지 않습니다. PowerPoint에서 .pptx 로 저장한 뒤 다시 올려 주세요." |
| 텍스트 추출 실패 | "문서에서 텍스트를 찾지 못했습니다. 스캔 이미지 PDF일 수 있습니다." |
| PPTX 텍스트 없음 | "슬라이드에서 텍스트를 찾지 못했습니다. 이미지로만 만든 발표자료일 수 있습니다." |
| LLM 호출 실패 | "AI 응답에 실패해 기본 분석 결과로 대체했습니다." (데모는 계속 진행) |
| 백엔드 미연결 | "백엔드 서버에 연결할 수 없습니다. `NEXT_PUBLIC_API_BASE_URL`을 확인하세요." |
