# 10. 품질 · 안전 요구사항 (모든 에이전트 필독 · 위반 시 훅이 차단)

## 환각 방지

- AI가 모르는 사실을 그럴듯하게 만들지 않는다. 근거 없는 문장은 **"원문 확인 필요"**로 표시한다.
- 수치는 원문 chunk와 연결하고, 숫자·단위가 맞는지 검증한다.
- 근거를 찾지 못한 항목은 삭제하지 말고 `unverified`로 넘겨 검증 모듈이 판단하게 한다.

## 근거 없는 점수 금지

**"정확도 92%" 같은 고정 점수 표기 금지.** 신뢰도 점수는 산식이 코드에 구현되어 있고
화면에서 설명 가능한 경우에만 표시한다.

## 고객용 자료

내부 정보일 수 있는 표현(내부 조직명·사내 시스템명·대외비·미확인 수치)을 제거하지 못하면
**경고를 남긴다.** 결과 상단에 "공개 전 검토 필요" 배지를 띄운다.

## 프롬프트 · 비용

- 긴 문서는 chunk 단위로 처리하고, **원문 전체를 무제한 프롬프트에 넣지 않는다.**
- 각 LLM 호출의 입력 크기 상한을 코드에 명시한다.

## 오류 처리

API 실패 / 미지원 파일 / 빈 문서는 **명확한 한국어 오류 메시지**를 반환한다.
빈 결과나 스택트레이스를 그대로 화면에 노출하지 않는다.

## 비밀정보

- 실제 API 키를 저장소 파일에 쓰지 않는다. `.env.example`에는 **변수 이름만**.
- 실제 값은 `.env`(gitignore 대상)에만 둔다.
- PreToolUse 훅이 `sk-`, `sk-ant-`, `AIza` 등 키 패턴 기록을 차단한다.

## README 필수 항목 (한국어)

로컬 실행 / 환경변수 설정 / **mock mode 실행법** / 배포 방법.

## 사람 검토 단계

이 도구는 발표 준비를 **가속**하는 것이지 사람 검토를 대체하지 않는다.
검증 리포트는 "확인이 필요한 지점"을 알려주는 것이며, 최종 책임은 발표자에게 있다는 문구를
결과 화면과 README에 명시한다.
